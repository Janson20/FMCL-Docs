插件开发 ​

FMCL 的插件以 .fmpl 压缩包分发，包含 plugin.json 清单与 Python 模块；可以注册钩子、导出 API、 提供配置与数据目录，也可以提供 QML 页面并登记到一级导航。

快速开始 ​

1. 创建插件项目 ​

my-plugin/
├── plugin.json         # 插件清单（必需）
├── __init__.py         # 入口模块（必需，必须导出 PluginBase 子类）
├── icon.png            # 插件图标（可选，推荐 128x128 PNG）
├── ui/                 # QML 页面（可选，ui_api: 2）
└── ...                 # 其他模块文件

2. 编写 plugin.json ​

json
{
  "id": "com.example.my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "author": "Your Name",
  "min_fmcl_version": "3.0.0",
  "description": {
    "zh_CN": "这是一个示例插件",
    "en_US": "An example plugin"
  },
  "permissions": ["ui.notification", "data.store"],
  "dependencies": {},
  "tags": ["utility"],
  "entry": "__init__"
}
字段必需说明
id是全局唯一标识，反向域名格式
name是显示名称，最长 64 字符
version是SemVer 版本号，如 1.0.0
author是作者名称
min_fmcl_version是最低兼容的 FMCL 版本
max_fmcl_version否最高兼容的 FMCL 版本，不填表示无上限
description否多语言描述字典
permissions否请求的权限列表
dependencies否依赖的插件及版本约束
conflicts否冲突的插件及版本约束
tags否标签列表
entry否入口模块名，默认 __init__
ui_api否界面扩展协议版本：1（旧界面协议，仅兼容非 UI 钩子）或 2（QML 页面）

3. 编写插件类 ​

python
# __init__.py
from plugin_manager.base import PluginBase, HookPoint


class MyPlugin(PluginBase):

    def get_default_config(self) -> dict:
        return {"enabled_feature": True}

    def on_load(self) -> None:
        """模块加载后调用"""
        self.log("插件模块已加载")

    def on_enable(self) -> None:
        """插件启用时调用，在此注册钩子、创建 UI"""
        self.log("插件已启用")

        self._manager.register_hook(
            self.manifest.id,
            HookPoint.GAME_POST_LAUNCH,
            self._on_game_launched,
            priority=100,
        )

        self.notify("插件就绪", "我的插件已启动", "info")

    def on_disable(self) -> None:
        """插件停用时调用，清理资源"""
        self.log("插件已停用")

    def _on_game_launched(self, **kwargs):
        version_id = kwargs.get("version_id", "unknown")
        pid = kwargs.get("pid", 0)
        self.log(f"游戏已启动: {version_id} (PID: {pid})")
        self.notify("游戏已启动", f"版本: {version_id}", "info")

4. 打包为 .fmpl ​

将项目目录压缩为 .zip，然后重命名为 .fmpl：

bash
# Windows PowerShell
Compress-Archive -Path my-plugin/* -DestinationPath my-plugin.fmpl

# Linux / macOS
cd my-plugin && zip -r ../my-plugin.fmpl .

5. 安装测试 ​

  1. 打开「设置」→「插件」→ 插件管理器。
  2. 点「从文件安装」选择 .fmpl 文件。
  3. 在权限确认弹窗中授权，插件会自动启用。

插件生命周期 ​

SCANNED → LOADING → LOADED → ENABLED → (DISABLED | ERROR)
阶段说明
SCANNED插件目录被发现，plugin.json 已读取
LOADING正在通过 importlib 加载 Python 模块
LOADED模块导入完成，实例创建，on_load() 已调用
ENABLEDon_enable() 已成功执行，插件正常运行
DISABLED用户主动禁用，on_disable() 已调用
ERROR运行中出错，不影响其他插件与启动器

界面扩展（UI API v2） ​

FMCL 当前只提供 QML 界面。插件要出现在导航中，必须提供 QML 组件并使用 ui_api: 2。 声明 ui_api: 1 的旧界面协议仍可安装与启用，但界面部分不会加载，管理器会标出「界面不受支持」； 非 UI 钩子（游戏启动、下载、通知等）不受影响。

1. 声明 ui_api ​

json
{
  "id": "com.example.my-plugin",
  "name": "我的插件",
  "version": "2.0.0",
  "author": "Your Name",
  "min_fmcl_version": "3.0.0",
  "ui_api": 2,
  "permissions": ["ui.extend", "data.store"]
}

ui_api 缺省为 1，只有 ui_api >= 2 的插件才会被 QML 界面采集页面。

2. 注册页面 ​

在 on_enable() 里注册 UI_PAGE_REGISTER 钩子，返回一个页面字典或它的列表：

python
from plugin_manager.base import HookPoint, PluginBase


class MyPlugin(PluginBase):

    def on_enable(self) -> None:
        self._manager.register_hook(
            self.manifest.id,
            HookPoint.UI_PAGE_REGISTER,
            self._register_pages,
        )
        self._manager.export_api(self.manifest.id, "get_stats", self._get_stats)

    def on_disable(self) -> None:
        pass

    def _register_pages(self, **kwargs):
        return [
            {
                "id": "main",                      # 路由 id 会拼成 plugin/<插件 id>/main
                "title": "我的插件",                # 直接显示的名字
                "icon": "plugin",                   # 可选，只能用启动器已有的图标名
                "order": 100,                       # 可选，插件页之间的排序
                "qml_url": "ui/Main.qml",           # 相对插件目录，或绝对路径
            }
        ]

    def _get_stats(self, **kwargs):
        return {"count": 42}
字段说明
id必填，[A-Za-z0-9_.-]，最长 64；路由为 plugin/<插件 id>/<id>
title必填（空则回落插件名）；直接显示，不经过语言文件
qml_url必填，必须以 .qml 结尾，且解析后必须落在插件安装目录内
icon可选，只接受 qml/assets/icons 中已有的图标名
order可选整数，插件页那一段按它稳定排序

页面会作为一级导航项出现在侧栏底部的「插件」分组；禁用或卸载插件时路由一起撤销。

3. 页面取数 ​

插件页面是普通 QML 组件，与内置页面共用同一套上下文属性：Theme、Tr、Nav、Shell、 Dialogs、Plugins。向 Python 侧取数走导出的 API：

qml
import QtQuick
import QtQuick.Layouts

Item {
    Column {
        Text { id: label; text: "..." }

        Component.onCompleted: {
            var data = Plugins.call("com.example.my-plugin", "get_stats", {})
            label.text = "count = " + (data ? data.count : "?")
        }
    }
}
  • Plugins.call(owner, api, args)：args 是 dict（关键字参数）或 list（位置参数），无参可省略。
  • 调用在主线程执行，插件 API 中不要做长耗时工作（下载、压缩请放到自己的线程）。
  • 异常会转成状态条错误并返回 null。

4. 插件向页面推送 ​

页面需要「后台数据变了就刷新」时，插件调用 emit_ui_event：

python
self.emit_ui_event("stats_changed", {"count": 43})

QML 侧监听：

qml
Connections {
    target: Plugins
    function onPageEvent(owner, name, payload) {
        if (owner === "com.example.my-plugin" && name === "stats_changed")
            refresh()
    }
}

安全边界：QML 页面与插件 Python 代码同等信任（都能执行任意代码），启动器不做沙箱。 权限弹窗管的是启动器提供的 API，不是 Python 本身的隔离，请只安装来源可信的插件。

权限列表 ​

权限风险说明
filesystem.read低读取文件（排除启动器核心目录）
filesystem.write中写入文件（仅 .minecraft 与插件数据目录）
network.http低HTTP(S) 请求（通过启动器 UA 代理）
network.socket高原始 Socket 连接
ui.extend低注册标签页、侧边栏、设置面板
ui.notification低弹窗与通知
core.download中注册自定义下载源
core.version中注册自定义版本源
core.launch_hook高游戏启动前、后钩子
core.process高执行外部进程
data.store低持久化存储（插件数据目录）
data.settings中读取与修改启动器设置

钩子点 ​

钩子策略参数说明
app.startupALL—启动器初始化完成
app.shutdownALL—启动器关闭前
game.pre_launchCOLLECTversion_id, command游戏启动前（可修改启动命令）
game.post_launchALLversion_id, pid游戏启动后
game.stoppedALLexit_code游戏进程停止
game.crashedCOLLECTcrash_report游戏崩溃后
version.pre_installFIRSTversion_id, mod_loader版本安装前
version.post_installALLversion_id, success版本安装后
version.pre_removeFIRSTversion_id版本删除前
server.pre_startFIRSTserver_name服务器启动前
server.post_startALLserver_name, process服务器启动后
server.stoppedALLserver_name, exit_code服务器停止
ui.tab.registerCOLLECT—注册主界面标签页（旧界面协议）
ui.sidebar.registerCOLLECT—注册侧边栏项目（旧界面协议）
ui.settings.registerCOLLECT—注册设置条目
ui.page.registerCOLLECT—注册 QML 页面（ui_api: 2）
download.pre_downloadCOLLECT—文件下载前（可修改 URL）
download.post_downloadALL—文件下载完成
策略含义
ALL按优先级依次调用所有处理器，不关心返回值
COLLECT依次调用，收集所有返回值到列表
FIRST依次调用，返回第一个非 None 值（可用于阻止操作）
SHORT_CIRCUIT依次调用，某个返回 True 则停止

插件配置 ​

每个插件有独立的配置空间，自动持久化到 plugins/configs/{plugin_id}.json：

python
class MyPlugin(PluginBase):

    def get_default_config(self) -> dict:
        return {"api_key": "", "interval": 60}

    def on_enable(self) -> None:
        api_key = self.config.get("api_key", "")
        self.log(f"API Key: {api_key[:4]}...")

        self.config["interval"] = 120
        self._manager.save_plugin_config(self.manifest.id)

插件数据目录 ​

每个插件有独立的持久化数据目录 plugins/data/{plugin_id}/：

python
class MyPlugin(PluginBase):

    def on_enable(self) -> None:
        # self.data_dir 自动指向 plugins/data/{plugin_id}/
        db_path = self.data_dir / "cache.db"
        self.log(f"数据目录: {self.data_dir}")

插件间通信 ​

插件可以导出 API 供其他插件使用，并在 plugin.json 中声明 exports：

json
{
  "id": "com.example.plugin-a",
  "exports": ["get_version"]
}
python
class PluginA(PluginBase):
    def on_enable(self) -> None:
        self._manager.export_api(self.manifest.id, "get_version", self._get_version)

    def _get_version(self):
        return "1.0.0"


class PluginB(PluginBase):
    def on_enable(self) -> None:
        get_version = self._manager.get_plugin_api("com.example.plugin-a", "get_version")
        if get_version:
            self.log(f"插件 A 版本: {get_version()}")

插件之间会做版本约束、循环依赖检测与拓扑排序；更新失败自动回滚旧版本。

最佳实践 ​

  1. 最小权限：只请求插件实际需要的权限。
  2. 异常处理：on_enable() 中的异常会使插件进入 ERROR 状态，需要充分处理。
  3. 资源清理：on_disable() 中释放所有资源（线程、文件句柄、网络连接）。
  4. 日志规范：使用 self.log() 而不是 print()，方便统一排查。
  5. 版本约束：使用 SemVer，依赖中写 >=1.0,<2.0 这类范围。
  6. UI 线程安全：界面操作都在主线程，长耗时工作放插件自己的线程，完成后用 emit_ui_event 通知页面刷新。
